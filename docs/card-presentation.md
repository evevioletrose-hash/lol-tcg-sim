## V1: Artwork identity and fallback

Artwork is presentation data, not a printed card field or profile property. src/cards/card_artwork.gd maps explicit edition-qualified IDs to existing imported Texture2D resource paths. Currently the single binding is tabletop:1-001 -> res://assets/card arts/1-001.jpg. The rare tabletop 1-400 and historical digital 1-001 are not aliases. No research archive assets copied, no new art generated, no assumed match by display name. Existing references and 3D assets remain untouched.

Shared Card/img/Artwork contains an aspect-preserving TextureRect and a neutral text fallback, with separate apertures for existing B.B., Item and Surprise layout. Card.populate binds the texture every time (including draft preview); missing/unmapped art clears old texture and shows labeled fallback. Card.set_face hides artwork while face down. Unmapped differs from missing/unimported resource internally. No Place scene yet; incomplete definitions remain text-only. Current art is displayed as-is, not a claim of official source/authenticity or visual crop quality.

To add another verified asset, import it in Godot and add an explicit edition-qualified mapping; preserve sources separately in the archive. No implicit filename search. Runtime loads use ResourceLoader; when an export preset is introduced, include these dynamically referenced artwork assets (export all resources or explicit selections), and test exported builds. There is no export verification yet.

Run -- --card-artwork-test after editor import. Exercises existing supported typed scenes, known asset, wrong edition, missing path, fallbacks, visibility, face-down behavior and reuse of one card. Expected at the original catalogue: 1 available, 305 placeholders, 5 unsupported Place records. Real rendered composition, image suitability and layout remain for manual inspection. V2 will refine the first B.B. design and typography; V3 extends the design to other types, V4 3D binding, V5 finishes/animation.

## V4: Portable 3D card proof of concept (pending local acceptance)

Original src/cards/3dCard.tscn is a historical composition experiment: BB_Card SubViewport at 1887 x 2102, a camera with hard-coded Label3D name/club/power/style/groove, separate lit and rotating diamond/disco sphere meshes, a sprite using ViewportTexture, a thin four-surface card mesh (Card, Black, Border_Rare, ViewPort), and a separately staged MERGED_popheart character hierarchy with rigged meshes. The inspected scene does not establish a reusable data contract; its label defaults differ from the catalogue (e.g. Style 10/Groove 4). Original scene and Blender assets remain unchanged. The rotator also compares radians to 360; not used in the new proof of concept.

Reusable src/presentation/card_object_3d.gd is a Node3D independent of Game, Card, profiles and catalogue. configure(front_texture, back_texture, dimensions, optional_mesh) builds a physical body, normalized authored mesh or BoxMesh fallback, and two textured quads. It overrides body material per instance, uses unshaded alpha-scissor faces, and does not own texture producers. The host can put this object in a world, on a table or in an inventory inspection viewport; dimensions are host-defined world units. It is not a package or dependency of Lacunae yet. No changes to that repository. Reuse code and interface, not necessarily branded assets.

LOL-specific src/card_viewer/card_inspector_3d.gd is an adapter: two ordinary card scenes built from the same projected definition produce front and back textures via separate one-shot SubViewports. One isolated 3D viewport hosts the object and an orthographic camera. Normal Workshop offers Inspect in 3D / Return to 2D, left drag rotation and existing flip button; switching selection or refreshing destroys the inspector. All typed cards supported including landscape; incomplete slots remain text-only. 2D remains default; if setup fails it stays visible. Archivist remains 2D. Original card_mesh.tres reused without Blender; no authored asset required for the generic body. No animated 3D stat icons, character models, physics, interaction in FPS, caching/batching, material finishes or export validation yet. Per-card face generation duplicates presentation nodes, not card data. Texture rendering and mobile renderer compatibility require real graphical inspection; headless test only validates node/field/orientation lifecycle, not rendered pixels. For many cards in-world, share/capture static textures instead of allocating live viewports per card; profile GPU memory and frame time first.
